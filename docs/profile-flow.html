the key insight

The profile is not a page. It is a state of the graph. When you arrive at /practitioner/eli-okun, the same Three.js canvas loads — but the camera focuses on Eli's node, the Reader contextualises his neighbourhood, forces reshape around his position, and overlay panels show his edges. The graph becomes his profile by centering on him.

This maps directly to the existing CONTEXTUALISE mode in ai-voice.js

The system already does this. When you click a node in the living canvas, contextualise() fires: the force engine focuses on that node, the Reader interprets the neighbourhood, forces reshape the field. A profile URL is just a deep-link into that state.

implementation map

What changes in the existing code

The living canvas already has 90% of what profiles need. This maps the profile features to existing modules and marks what's new.

URL routing

main.js · new
Parse URL on load. If /practitioner/:slug, fetch the practitioner node, then call contextualise() with their ID instead of narrate(). The camera focuses, forces reshape. Everything else is the same.

CONTEXTUALISE mode

ai-voice.js · exists
Already handles node focus. The profile state is a persistent CONTEXTUALISE — it doesn't revert to NARRATE when you click empty space. Add a profile mode flag.

Force focus

force-engine.js · exists
Worker already supports focus message. Attracts neighbouring nodes, dampens distant ones. No change needed.

Profile panels

text-overlay.js · extend
New panel type alongside spatial text. Positioned at fixed screen locations (not anchored to 3D nodes). Populated from the profile API endpoint. Grouped by edge type.

Profile API

data-layer.js · extend
New fetch: GET /api/practitioner/:slug. Returns node + edges grouped by type + metrics. Feeds the profile panels and the CONTEXTUALISE call.

Node colours

renderer.js · exists
Already colour-codes by type. Artworks are #a8c4e0, practitioners #d4a574, concepts #c2dbbf, scenes #7aff9c. No change.
What's genuinely new: URL parsing in main.js (~20 lines), a profile mode flag (~10 lines), the profile panel component in text-overlay.js (~80 lines), and a fetch call in data-layer.js (~15 lines). Total: ~125 lines of new code. Everything else — the renderer, the force engine, the AI voice, the interaction handler — already does what profiles need.
