06 — Merge Boundary

What auto-merges vs. what queues for review

Determined at the endpoint, not by the client. Self-report = no friction. Speaking for others = review. Contests = always accepted.

Action Example Result
Writing about yourself Eli adds his own bio, artworks, practice concepts Auto-merge
Adding your own artworks CREATED_BY edge pointing to yourself Auto-merge
Creating new concepts / scenes / institutions Eli proposes concept:ritual infrastructure Auto-merge
Linking yourself to existing nodes EXHIBITED_AT, BELONGS_TO, PRACTICES from yourself Auto-merge
Creating edges TO other practitioners COLLABORATES_WITH(eli → maya) — needs Maya's confirmation Intake queue
Creating edges FROM others PRACTICES(maya → concept:X) — can't speak for someone else Intake queue
Edges between unrelated nodes EXHIBITED_AT(casey reas → ZKM) — not Eli's data Intake queue
Filing a contest CONTESTS edge against any existing edge Always accepted

08 — Open Questions

For the team call

1. Panel F visibility

Do frontier signals and self-reported tensions show publicly? Instinct: yes, with per-signal opt-in. It's the differentiator. But practitioners must consent.

2. Contest surfacing

When someone files CONTESTS against a profile edge — immediate (with provenance) or after curator review? Principle says immediate. Practice may say review.

3. URL format

/practitioner/:slug (existing) vs /p/:slug (shorter for sharing). Keep canonical and add alias? Or migrate?

4. File uploads

Essential for onboarding (install photos, documentation)? Or defer to post-v0.1? Adds storage infrastructure (S3/R2).

5. Reader position statement

The one-liner in the profile header ("Bridges installation art and..."). Pre-computed + cached? Or live Reader agent call? Cost vs. freshness.

6. Schema freeze: 5a-5c

batch_id (import rollback), node_aliases (cross-source dedup), signal status (revocation mechanism). Include in freeze or defer?
